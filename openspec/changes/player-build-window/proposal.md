# Proposal: Player Build Window

## Why

The fight view answers "what is this player running" with two ability bars and a line of set counts (`5x Deadly Strike, 2x Zaan`). It does not answer "how is it put together": which slot holds which set piece, with what trait and enchant, whether a poison is slotted, and which mundus stone and food the player pulled with. Raid leads get that today by asking the player for a SuperStar screenshot.

The encounter log already records all of it for every group member at the start of every fight. The app parses those fields and then discards everything except the set counts and the bars.

## What Changes

- **Build window**: clicking a player's name in the fight view (detail or compact) opens a modeless window for that player in that fight. Hovering a name underlines it in the link color and shows a tooltip, as the cue that it can be clicked. The window shows:
  - a header: account name, character name, race, class, champion points, role, and the fight it belongs to;
  - both ability bars, front above back, with the same hover (ability name) and click (ESO-Hub page) as the fight view, and the same line of scribed skills with their scripts;
  - a gear grid, one row per slot: slot, set (linked to ESO-Hub), pieces of that set active, quality, trait, enchant, enchant quality;
  - a poison row under a weapon bar when a poison is slotted there;
  - the mundus stone or stones, and the food or drink buff, both read from the long-term effects the log lists for the player at combat start.
- **Engine**: each player in a completed fight carries the full per-slot gear, mundus and food data, in live monitoring and in review mode. Today only set counts reach the GUI.
- **Bundled reference data**, generated by scripts at build time, never fetched at runtime:
  - poison names (50 items) from UESP's item database, because the log gives a poison only as an item id;
  - food and drink buff ability ids (92) from the LibFoodDrinkBuff addon, to tell a food buff from the other long-lived effects.
- **Documentation corrections**: `ESO_GEAR_SLOTS.md` and the README state that the log carries 13 gear slots and never the back-bar off hand. Real logs carry 17 slot names (including back-bar off hand, both poison slots and costume) and simply omit empty slots.

Not changing: the fight summary, *Copy fight*, split files, archiving, settings. No new setting is added.

Out of scope, decided with the maintainer on 2026-10-05:

- Item names, weapon type and armor weight. The log does not carry them; they would need a bundled table of every equippable item id.
- Attributes, the damage/crit/penetration/resistance block, skill points and champion point stars. The log does not carry them (only a few champion stars appear as effects).
- ESO-Hub links for mundus stones, traits and enchants; copying a build as text; stepping between players inside the window.

## Capabilities

### New Capabilities

- `player-build-window`: opening a per-player build window from the fight view, and what it shows: header, stacked ability bars, per-slot gear grid with set piece counts, slotted poisons, mundus stone and food or drink buff, all taken from the encounter log's combat-start snapshot plus bundled reference data.

## Impact

- **Code**: a new Qt-free module for build data and labels; `ESOLogAnalyzer` keeps each player's race and long-term effects and adds build data to the fight entry's player dicts; a new render module and dialog in `src/gui/`; `FightView` routes a new internal link and applies the hover cue, taking over the search highlight list from `MainWindow` so the two do not overwrite each other; `fight_render` wraps player names in that link; `MainWindow` opens and refreshes the dialog.
- **Data and scripts**: `data/items/poisons_en.json` and `data/buffs/food_drink.json` with one generator script each; both folders added to the PyInstaller `datas`.
- **Credits**: About dialog and README gain UESP's item database and LibFoodDrinkBuff.
- **Performance**: about 16 small dicts per player per fight, built once when the fight ends. No per-event cost during combat.
- **Compatibility**: fight entries only gain keys. The golden test serializer reads named keys, so existing goldens are unaffected.
